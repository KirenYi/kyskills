# 第 0 步：先看原片

拿到原片后，先看清楚它现在是什么状态，再决定做哪几步。**用户已经做过的，不重做。**
（来自第 2 期的教训：原片已经剪过、加过速、烧了字幕，默认流程却又加速一次，还用黑条遮掉原字幕再重排。）

## 怎么看

```bash
ffprobe -v error -show_entries format=duration:stream=codec_type,width,height,avg_frame_rate -of compact <原片>
ffmpeg -i <原片> -vf "fps=1/5,scale=270:-1,tile=6x2" -frames:v 1 grid.png   # 抽 12 帧看画面
```

再转写一遍（whisper），看句间停顿多不多、有没有重复说的句子。

## 判断表

| 看到的 | 说明 | 怎么做 |
|---|---|---|
| 画面里已经有字幕（每帧下方都有固定样式的字） | 用户自己加过字幕 | **不加字幕，不遮原字幕**。叠加的画面要避开字幕区 |
| 语速明显偏快、停顿很少（超过 0.25 秒的停顿只有几处） | 可能已经加过速或剪过 | **不再加速、不再精剪**。拿不准就问用户 |
| 同一句没有重复说 | 已经挑过片段 | 跳过第 6、7 步（剪辑表、精剪），整条直接用 |
| 竖屏（比如 1080×1920） | 脚本默认按横屏 16:9 处理 | 不用 `prep.py` 的缩放；转成固定 30 帧后整条直接用。叠加内容按 `platforms.md` 的竖屏安全区放 |
| 横屏 4K、没剪过、没字幕 | 标准情况 | 走完整流程 |

## 拿不准时

直接问用户一句：「这条原片是剪过的吗？字幕、加速是你自己加的吗？」不要猜了以后按默认流程做完再返工。
