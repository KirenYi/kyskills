# ky-follow

检查一篇稿子在哪里会让读者跟不上。适用于观点文章、视频口播稿、图文文案、帖子。

**语言**：用用户使用的语言回复。

## 原理

作者读自己的稿子，会自动补上脑子里的推理，所以「读起来顺不顺」不能当判断依据。这叫知识的诅咒。

AI 默认也有两个毛病：它什么都懂，读到跳跃时自己就补上了，于是回一句「逻辑清晰」；或者你问它「有没有逻辑问题」，它就硬找出一堆，连留白和钩子都算进去。

这个 Skill 的做法：先写清读者知道什么，再找一个没看过分析的读者冷读，然后拆出论证每一步依赖什么，两边对照，找出读者补不上的地方。

四个判断贯穿全程：

1. **断层是相对于读者的。** 同一篇稿子，懂行的人觉得顺，外行觉得跳。读者没定义，就没法判断。
2. **门槛和断层要分开。** 门槛是作者知道它在哪、知道会筛掉谁、也愿意付这个代价的难点；断层是作者没意识到的难点。目标不是抹平所有难点，否则内容会变得无脑，而是让每个难点都是有意的。难度可以来自思考的深度，不该来自信息的缺失：缺一个术语或背景，补一句的成本很低；需要读者真正想一想的推理，才值得保留为门槛。
3. **留白不是断层。** 读者凭已知信息想一下就能推出来的步骤，不写反而更好，读者会有「原来如此」的感觉。每一步都写满，内容就成了说教。
4. **钩子不是断层。** 开头故意抛出的问题、悬念、反常识的结论，只要后面接回来了，就不算断层；没接回来，才是。

## 输入

- 稿子：文章、口播稿、文案都可以
- 形式和平台：短视频、长视频、图文还是长文。决定「开头」有多长、观众能不能回看
- 读者设定：先找 `~/.config/kyskills/ky-follow/readers.md`，里面有对应的读者设定就直接用

缺少形式或读者设定时，不要停下来追问。根据稿子内容推一版，标为「假设」，在报告末尾请用户确认。

## 流程

### 第 1 步：读者设定

设两个读者，按「知道什么、相信什么」来定义，不按年龄、职业这类人群属性定义。

- **门口读者**：刷到或点开的任何人，决定开头留不留得住，影响曝光。
- **目标读者**：作者希望留下、愿意跟着想下去的人，影响转化。

每一栏写成具体词条，比如具体的概念、工具、经验。「有一定基础」这种描述没法拿来对照，不要写。

```
【门口读者】
知道：…
不知道：…
相信：…（会影响他接不接受论点的既有看法）
【目标读者】
知道：…
不知道：…
相信：…
```

「相信」这一栏很重要：读者不缺知识，但持有相反的看法时，跳过论证一样接不上。

### 第 2 步：冷读

这一步要在结构分析之前做，并且由一个没看过分析、也不知道作者意图的读者来读。分析过结构的模型已经知道作者想说什么，也会中知识的诅咒。

能开子代理（subagent）时，开一个新的子代理，只给它读者设定和稿子，不给作者的说明、对话背景和你的分析。分别扮演门口读者和目标读者，给它这样的要求：

> 你是【门口读者 / 目标读者】，你只知道下面这些：【读者设定】。只用这些知识和稿子里已经出现的内容，逐段读这篇稿子。每段写：
> 1. 我理解的意思（一句话）
> 2. 哪里卡住了，或者哪里我不接受
> 3. 我猜下一段会讲什么
> 4. 我会不会在这里离开，为什么
> 不要评价写得好不好，也不要给修改建议。

没有子代理时，自己先做冷读，写完再开始第 3 步；冷读时严格只用读者设定和稿子里已经出现的内容。

### 第 3 步：论证链和依赖对照

**拉出论证链。** 每个节点一句话，标出位置：文章标段落；口播稿引那一句的开头几个字，再加估算时间（中文口播大约每秒四五个字，从开头累计），方便发布后对照留存曲线。纯修饰、过渡、抒情的句子不算节点。再写出作者脑子里的完整链，稿子里没写出来的步骤放在方括号里：

`N1 → [隐含：X] → N2 → N3`

**连接词测试。** 相邻两个节点之间试着插「因为、所以、但是、比如、也就是说」：

- 一个都插不进去：断层。
- 只能插「另外、还有」：内容在并列堆砌，论证没有往前走。
- 插入只为检测，不建议作者真的加上。

**依赖对照。** 每个节点用到的概念、术语、前提、前面的节点，逐个对照读者设定，标为：

- **已知**：读者设定里有，或者这个节点之前已经交代过。后面才交代的不算。
- **可推**：读者想一下就能得出。这是留白，不要建议补。
- **未知**：设定里没有，前文没交代，也推不出来。这是断层候选。

**再看这几种常见的跳：**

- **因果缺环**：方括号里的隐含步骤连着两步以上，读者很难自己补上。
- **新概念太密、顺序反了**：一处同时冒出好几个新东西；或者先给名词再解释。好的顺序是先举例子，再说它叫什么，最后拿它推结论。
- **概念漂移**：同一个词前后意思变了。
- **尺度跳跃**：从一个案例跳到「所有人」「都会」「必然」，中间没论证范围。
- **问题错位**：读者看完上一段，心里最想问的问题，下一段没有接住。
- **钩子没接回**：开头抛出的问题或悬念，后面没有回答。

### 第 4 步：合并判定

把冷读和第 3 步的结果放在一起：

- 两边都指出的问题，排在最前面。
- 只在冷读里出现的：回头查第 3 步是不是漏了某个依赖。
- 只在第 3 步出现、冷读没卡住的：多半读者能自己补上，降级或删掉。

再按位置判断这个难点是断层还是门槛：

- **开头不能有门口读者不知道的东西。** 这是唯一的硬规则。「开头」指读者或观众决定要不要继续的那一段：短视频大约是前十几秒，图文和长文是第一屏。开头流失会直接伤害曝光。
- **难度大体往后走高。** 同一个难点放在前段是断层，放在后段，筛掉的多半是本来就不会转化的人，可以是门槛。
- **门槛要说得出「筛掉谁、为什么值得」。** 说不出来的，按断层处理。一篇里有意的门槛不宜多，多了就不是筛选，是劝退。
- **看难点从哪里来。** 来自术语或背景缺失的，几乎都该补；来自需要思考的推理或反常识判断的，可以保留。

**视频更严。** 读者卡住可以往回读，观众卡住通常直接划走。同样的跳跃，在口播稿里代价更大。

### 第 5 步：最小改法

每个断层只给一个最小改法，按改动从小到大选：

1. **补前提**：用一句话交代缺的那一步或那个背景
2. **补例子**：用读者已经知道的东西接住新概念
3. **拆步骤**：一个大跳拆成两步
4. **后移**：把难点挪到后段
5. **删掉**：补上它要三段以上，它可能是另一篇稿子

每条写清：在哪句之后、读者此刻会问什么（「为什么？」「这是什么？」「怎么突然说到这个？」「凭什么这么大的结论？」）、可以直接放进去的一句示例。不要重写整篇，作者的语气和判断是内容的核心。语言润色交给 ky-write。

## 输出格式

```
## 读者设定（假设 / 用户提供）
两个读者的清单

## 整体结构（只在有问题时写）
各段大意连起来构不成论证时，先在这里指出。这种问题改句子解决不了。

## 论证链
N1（位置）→ [隐含：…] → N2 → …

## 断层（按严重程度排序）
1. 位置：……之后
   读者会问：……
   为什么接不上：……（冷读 / 依赖对照 / 两边都有）
   最小改法：……（附一句示例）

## 保留的门槛和留白
- 位置：筛掉谁、为什么值得；或者为什么读者能自己补上

## 预测流失点
- 位置（口播稿加估算时间，如「约 3–11 秒」）：原因（发布后可以拿留存曲线对照）

## 需要作者确认
- 读者设定里的假设
- 判断不了是不是有意设置的难点
```

断层只列真正的问题，宁缺毋滥；没问题的部分不用逐条说没问题。稿子本身很顺时，直接说没找到断层，并说明是相对哪个读者。

## 保存读者设定

报告结束时，如果读者设定是推出来的，问用户一句要不要存下来。用户同意或给了修改，就写进 `~/.config/kyskills/ky-follow/readers.md`（不存在就创建）。一个文件可以放几套设定，用标题区分，比如按账号或栏目。下次检查时先读这个文件。

用户带回发布后的数据（留存曲线、评论里的「没看懂」「不同意」）时：对照之前预测的流失点，说明读者设定里哪一条可能写错了，建议怎么改。「没看懂」多半指向断层；「我不同意」通常说明门槛在起作用。

## 示例

稿子里的一句：「早上的时间最值钱，所以想成事的人都应该五点起床。」

- 论证链：N1 早上的时间最值钱 → [隐含：早上值钱是因为没人打扰] → [隐含：五点起床就能得到这段时间] → N2 想成事的人都该五点起床
- 连接词测试：N1 和 N2 之间能插「所以」，但读者会问：「凭什么是五点？晚上没人打扰不也一样？」
- 判断：因果缺环（连续两步隐含）加尺度跳跃（「都应该」）。筛掉的是会追问「真的吗」的人，这些人正是目标读者，所以是断层，不是门槛。
- 最小改法：补出「值钱」的真实原因，再把结论收窄。比如：「早上值钱，不是因为早，而是因为没人找你。对大多数上班族来说，这段时间只在早上。」

示例只示范判断方式，不要照搬到别的稿子上。
