# 口播稿模式

适用：视频口播稿、短视频脚本、直播提纲。观众是"听"文字，不是"读"文字，所以规则和文章不同。

## 工作流程

1. 用一句话复述这条视频的核心观点。复述不出来，先问作者，不要硬改。
2. 按下面的规则逐项检查，记下问题位置。
3. 输出三部分：
   - 问题清单：最多 8 条，按影响从大到小排，标明"必改 / 建议改 / 可选"。
   - 修改后的口播稿：按"一行一句"排版，方便看提词器和后期断字幕。
   - 开头备选：给 3 个不同写法的前三秒开头。
4. 默认只动"必改"项，其余列出来由作者决定。

## 开头（前三秒）

- 第一句直接给结论、冲突或反常识的事实，不寒暄，不自我介绍。
- 禁用开场："大家好，今天我们来聊聊……""随着 AI 的快速发展……""你有没有想过……"（除非后面立刻接具体场景）。
- 好的开头类型：
  - 结论先行："跨境电商选品，90% 的人第一步就错了。"
  - 具体场景："上个月我一个产品亏了三万，原因很蠢。"
  - 反常识："AI 工具越多，一个人的公司反而越难做。"
- 开头里的数字、结论必须来自作者提供的内容，不要编。

## 句子

- 一句只说一个信息。超过 25 个字的句子拆开。
- 主语、动词放前面，少用长定语："这个我花了三个月才搞明白的问题"→"这个问题，我花了三个月才搞明白。"
- 少用书面连接词，换成口语：

| 书面 | 口语 |
|---|---|
| 此外 / 另外 | 还有 |
| 因此 / 由此可见 | 所以 |
| 然而 / 但是呢 | 但是 / 可是 |
| 首先、其次、最后 | 第一、第二 / 先……再…… |
| 即 / 亦即 | 就是 |
| 进行分析 | 分析 / 看一下 |
| 具有重要意义 | 很关键 / 直接删 |

## 节奏

- 每 15 到 20 秒（约 60 到 80 个字）要有一个推进：新信息、例子、转折或提问。
- 关键结论可以重复一次，换个说法说，观众听漏了还能接上。
- 适度语气词可以保留（"对吧""你看""说白了"），它们承担停顿和节奏；但同一个语气词全篇不超过三次。
- 段落之间用口头路标衔接："那问题来了""反过来说""我举个例子"，替代文章里的小标题。

## 听感

- 读出声检查。拗口、换气困难的地方必改。
- 避免听起来容易混淆的词：同音词、"其中/期中"这类听不出区别的词，换成更清楚的说法。
- 数字说得好记：
  - "48.7%"→"差不多一半"（精确数字留给画面上的字幕或图表）
  - "1,280,000"→"一百二十多万"
  - 一段里不要连续出现三个以上数字。
- 英文术语：第一次出现时，用一句中文说明它是什么；之后保持同一个叫法，不要一会儿英文一会儿中文。

## 结尾

- 停在最后一个有信息的地方，或给一个具体的行动（"你可以今天就试一下……"）。
- 禁用："总之""以上就是今天的全部内容""未来可期"。
- 引导关注或评论可以有，但只说一句，并且和内容有关："你踩过哪个坑，评论区告诉我。"

## 长度参考

- 中文口播语速大约每分钟 200 到 250 字。
- 输出时标注预估时长，超出作者设定的时长就提出删减建议，先删例子以外的铺垫。

## 不要做的事

- 不把口播稿改成书面文章腔。
- 不加作者没提供的事实、数字、经历。
- 不为了"口语化"加网络流行梗，除非作者原稿就是这种风格。
