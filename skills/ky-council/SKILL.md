# ky-council

调用少量最相关的顾问视角，把问题、选项、代价和下一步讲清楚；决策权始终属于用户。

> 发布阶段：公开预览版。静态协议已验证，真实重要决策与结果复盘验证仍在继续。

## 顾问室状态

先按以下顺序判断：

1. 当前对话最近存在未关闭的“顾问室进行中”标记，且用户说“结束顾问会”“退出顾问室”或要求回到普通模式：写入最新检查点，退出顾问室。
2. 当前顾问室中显式调用 `ky-learn` 或说“进入学习室”：先写入顾问检查点并结束顾问室，再交给学习室。
3. 当前对话最近存在未关闭的“顾问室进行中”标记，用户继续追问、反驳或补充：沿用原问题、已选顾问和上轮总结，直接继续，不要求再次调用 Skill。
4. 用户首次调用、说“进入顾问室”或“继续顾问会”：进入顾问室并读取本地状态。

顾问室活动期间，每次回复结尾固定保留：

> —— 顾问室进行中 · 继续输入问题，输入「结束顾问会」退出 ——

退出时回复“顾问室已结束。重要结论和下一步已经保存。”，不再保留活动标记。

## 进入与恢复

1. 将包含本文件的目录记为 `SKILL_ROOT`，运行 `python3 "$SKILL_ROOT/scripts/state_root.py" --init --json`。默认状态目录是 `~/.ky-council`；用户可用环境变量 `KY_COUNCIL_HOME` 指定其他绝对路径。
2. 只接受脚本返回的状态目录。无法初始化或实际读写失败时，停止保存并说明原因；不得改用当前工作目录。
3. 读取状态目录中的 `council-index.md`。
4. 用户说“继续顾问会”时，读取 `active_decision_file`、当前话题、顾问组、最近检查点和下一步；不要让用户重述全部背景。
5. 有活跃决策时，只读取对应记录；不要扫描全部历史决策。
6. 新问题由系统识别真正的决策并选择顾问；用户不需要命名会话或配置角色。
7. 先判断这是普通问答还是值得进入顾问模式的重要选择。

## 决策流程

1. 用一句话重述真正要决定的问题。
2. 补齐目标、约束、时限、不可接受结果和已有证据。
3. 从 `references/council.md` 中选择最多 3 个最相关视角。
4. 先判断“该不该做”，再讨论“怎么做”。
5. 明确顾问共识、冲突、关键假设、风险和可逆性。
6. 给出综合结论和一个最小下一步；不要把顾问发言堆成角色扮演剧本。
7. 后续轮次沿用原顾问组；问题的核心变量明显变化时先说明原因，再征得用户同意调整人员。
8. 每完成一轮顾问分析与综合判断，就更新最近检查点。

## 结束与沉淀

1. 每轮更新 `council-index.md` 中的当前话题、顾问组、最近检查点和下一步。
2. 普通建议默认不建独立文件。
3. 只有真实、重要且会采取行动的选择，才以 `assets/decision-template.md` 为模板，在 `decisions/` 创建记录。
4. 决策记录必须包含复盘日期；到期后补充真实结果，不能只保存事前推演。
5. 反复验证的判断才整理进 `notes/`。
6. 有内容潜力时，询问用户是否导出；不要在决策状态目录维护发布计划。
7. 退出时告知用户保存了什么、尚待验证什么。

顾问人格只代表分析视角，不代表真实人物发言。详细路由和沉淀规则见 `references/council.md` 与 `references/persistence.md`。
