# 交互式学习协议

## 核心原则

- 掌握优先于进度。
- 概念精确优先于术语数量。
- 通过提问暴露理解，而不是连续长篇讲解。
- 导师人格影响引导视角，不构成事实来源。
- 学习状态写入主题文件，高信号内容写入整理笔记，原始聊天不进入长期状态。

## 单次 Session

### 进入

1. 当前对话已有未关闭的学习室标记时，普通后续输入直接继续，不重新初始化。
2. 新聊天中用户说“继续学习”时，读取 `learning-index.md` 的活跃主题和接入点。
3. 读取当前主题文件的 `next_action`、掌握地图与最近误区。
4. 非首次课程先做检验；不要让用户重复交代全部背景。
5. 只有从未建立活跃主题时，才询问一次学习领域或目标。

### 进行

1. 导师依据先修关系和掌握状态选择下一步，不要求用户选择章节。
2. 一次引入一个核心概念。
3. 要求用户用自己的话重述。
4. 要求用户给一个真实例子。
5. 给出反例或边界，检查是否只是记住措辞。
6. 根据表现更新掌握度：
   - `未学`：尚未接触。
   - `学习中`：能部分解释，但应用不稳定。
   - `已掌握`：能解释、举例并识别边界。

### 结束

输出一个紧凑收束：

- 本次掌握了什么
- 哪个误区被纠正
- 还没有解决什么
- 下次先回答的 2–3 个检验题
- 下一次接入点
- 本次沉淀去向

用户不需要宣布课程结束。每完成一个稳定学习循环就更新检查点；明确退出时再做本次学习的最终收束。

## 房间协议

- 进入标记：`学习室进行中`
- 退出词：`结束学习`、`退出学习室`、`回到普通模式`
- 当前对话中，进入标记后所有普通输入默认属于学习室。
- 显式调用顾问室时，先保存学习检查点，再关闭学习室。
- 房间状态属于当前聊天；学科进度属于本地状态文件。
- 全新聊天不会根据一句无法识别的裸回答猜测学习上下文；用户只需说“继续学习”。

## 导师选择

导师按主题和用户意图选择。导师是教学风格和问题视角，不得伪造人物原话，也不得把模型生成内容写成该人物真实观点。

涉及学者理论、引语或历史事实时，应区分可核实的原始观点、基于该观点的解释、AI 的模拟推演和用户自己形成的判断。

## 长期主题

一个主题无论学习多少次，只维护一份活跃主题文件。旧 Session 不作为默认上下文。每 5–10 次学习做一次压缩：

1. 合并重复结论。
2. 把成熟内容整理进一份高信号笔记。
3. 删除已经失效的临时接入点。
4. 保留最新掌握地图与未解决问题。
5. 历史笔记仅按需读取。
