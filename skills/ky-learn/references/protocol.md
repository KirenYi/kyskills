# 交互式学习协议

## 核心原则

- 掌握优先于进度。
- 概念精确优先于术语数量。
- 通过提问暴露理解，而不是连续长篇讲解。
- 导师人格影响引导视角，不构成事实来源。
- 学习状态写入 MOC，成熟知识写入卡片，原始聊天不进入长期知识库。

## 单次 Session

### 进入

1. 当前对话已有未关闭的学习室标记时，普通后续输入直接继续，不重新初始化。
2. 新聊天中用户说“继续学习”时，读取学习总览的活跃主题和本地接入点。
3. 读取当前主题 MOC 的 `next_step`、掌握地图与最近误区。
4. 非首次课程先做检验；不要让用户重复交代全部背景。
5. 只有从未建立活跃主题时，才询问一次学习领域或目标。

### 进行

教学顺序、提问方式、掌握程度和复习规则以 `SKILL.md` 的「第一次学一个主题」「每一轮怎么教」「掌握程度」「开课复习」为准。这里只补充记录方式：

- 掌握地图每行一个概念：状态、能否解释、能否应用、最近检验日期。主干在前，枝叶在后。
- 误区写成「原来以为 → 实际上」，并注明是否属于「把握高却答错」。
- 推荐过的书或课写在主题 MOC 的「领域地图与引路人」一节，注明推荐时机和原因。

### 结束

见 `SKILL.md`「结束一次学习」。用户不需要宣布课程结束；每完成一个稳定学习循环就更新检查点。

## 房间协议

- 进入标记：`学习室进行中`
- 退出词：`结束学习`、`退出学习室`、`回到普通模式`
- 当前对话中，进入标记后所有普通输入默认属于学习室。
- 显式调用顾问室时，先保存学习检查点，再关闭学习室。
- 房间状态属于当前聊天；学科进度属于本地 MOC。
- 全新聊天不会根据一句无法识别的裸回答猜测学习上下文；用户只需说“继续学习”，不需要说明阶段。

## 导师选择

导师按主题和用户意图选择。导师是教学风格和问题视角，不得伪造人物原话，也不得把模型生成内容写成该人物真实观点。涉及学者理论、引语或历史事实时，应区分：

1. 可核实的原始观点
2. 基于该观点的解释
3. AI 的模拟推演
4. 用户自己形成的判断

## 长期主题

一个主题无论学习多少次，只维护一份活跃主题 MOC。旧 Session 不作为默认上下文。每 5–10 次学习做一次压缩：

1. 合并重复结论。
2. 把成熟内容升级为卡片。
3. 删除 MOC 中已经失效的临时接入点。
4. 保留最新掌握地图与未解决问题。
5. 历史 Source Note 仅按需读取。
